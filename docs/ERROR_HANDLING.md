# Обработка ошибок скачивания

## Задача и границы изменений

Автор самостоятельно написал получение URL, один `fetch`, проверку HTTP-статуса
и полное чтение ответа через `arrayBuffer()`. Затем попросил ИИ сначала запушить
исходную версию, а обработку ошибок добавить в новой ветке, запушить и смержить.

Первый этап касался одного запроса. Затем автор самостоятельно добавил измерение
времени, цикл из 10 запросов и расчёт скорости. Обработчики теперь выполняются
на каждой итерации; таймаут создаётся заново. Зависимости не добавлены.

## Как устроен код

1. `main()` проверяет аргументы до отправки запроса.
2. `new URL()` разбирает адрес; отдельно разрешены только HTTP и HTTPS,
   отклоняются адреса с логином или паролем.
3. `AbortSignal.timeout(30_000)` ограничивает запрос вместе с чтением тела.
4. `AbortSignal.any()` объединяет таймаут и отмену пользователем через Ctrl+C.
5. `fetch()` выполняет запрос; `!response.ok` обрабатывает HTTP-ошибки отдельно.
   Соединение с ошибочным HTTP-ответом отменяется без ожидания его тела.
6. `arrayBuffer()` читает тело до конца. После этого время и байты прибавляются
   к накопителям. Итоги выводятся только после всех 10 успешных запросов.
   Пустые успешные ответы корректно дают 0 байт.
7. `catch` передаёт ошибку в `describeError()`. Сетевой код обычно лежит
   в `error.cause.code`, потому что `fetch` оборачивает ошибку в `TypeError`.
8. `finally` удаляет обработчик SIGINT. `process.exitCode` задаёт код выхода,
   а `return` останавливает `main()` при ошибке без вывода неполного замера.

## Какие ошибки различаются

| Ситуация | Как обрабатывается |
| --- | --- |
| Нет URL, пустая строка, несколько аргументов | Сообщение с форматом запуска |
| Некорректный адрес | Отдельное сообщение об ошибке URL |
| Протокол не HTTP(S) | Сообщение о неподдерживаемом протоколе |
| Логин или пароль в URL | Сообщение, что такой URL не поддерживается |
| Неуспешный HTTP-статус | Печатаются числовой статус и описание сервера |
| DNS: `ENOTFOUND`, `EAI_AGAIN` | Различаются неизвестный хост и временный сбой DNS |
| `ECONNREFUSED` | Сервер отказал в соединении |
| `ENETUNREACH`, `EHOSTUNREACH` | Недоступна сеть или сервер |
| `ECONNRESET`, `EPIPE`, `UND_ERR_SOCKET` | Соединение оборвалось до конца загрузки |
| `ETIMEDOUT`, таймауты соединения, заголовков и тела Undici | Отдельные сообщения о сетевом таймауте |
| Истекли общие 30 секунд | Таймаут всего запроса, включая чтение тела |
| TLS: самоподписанный сертификат, неизвестный издатель | Отдельные сообщения о проверке сертификата |
| `CERT_*`, `ERR_TLS_*` | Общая категория прочих ошибок сертификата и TLS |
| `ERR_SSL_WRONG_VERSION_NUMBER` | Ошибка ожидаемого HTTPS-протокола |
| Цикл или слишком много редиректов | Сообщение о превышении числа перенаправлений |
| Слишком большие заголовки | Отдельное сообщение `UND_ERR_HEADERS_OVERFLOW` |
| Несовпадение размера с `Content-Length` | Загрузка не считается успешной |
| Повреждённое сжатие или другая ошибка чтения | Сообщение о невозможности полностью прочитать тело |
| `RangeError` при накоплении ответа | Сообщение об ограничении размера `ArrayBuffer` |
| Отмена через Ctrl+C | Отмена запроса и код выхода 130 |
| Другая ошибка запроса | Общее сообщение с кодом или именем ошибки, код выхода 1 |

Сообщения об ошибках идут в stderr, успешный результат — в stdout.
Обработанные ошибки не выводят стек и не печатают частичный объём как успешный.
Проверка TLS не отключается. Автоматических повторных попыток нет.

## Проверки

Команды: `npm run check` и `npm test`. Проверено 49 сценариев на Node.js 24.21.0.

- Локальный HTTP-сервер: чтение ответа двумя частями, пустой ответ, HTTP
  401/403/404/429/500/503 с незавершённым телом, цикл редиректов, оборванное тело,
  повреждённый gzip, ожидание заголовков и зависшее чтение тела.
- Реальная отмена запроса сигналом: Ctrl+C и таймаут. В тестовом дочернем
  процессе таймаут сокращён до 200 мс; в рабочем скрипте остаётся 30 секунд.
- Моделирование отказов: DNS, системные и TLS-коды, ограничение `ArrayBuffer`
  и неизвестная ошибка. Это проверяет классификацию ошибок, а не реальный
  сбой внешнего DNS-сервера или TLS-сертификата.
- Все ошибочные сценарии проверяют код выхода, stderr и отсутствие успешного
  количества байтов в stdout.
- Новый этап: ровно 10 запросов с полным чтением тел, отсутствие одновременно
  незавершённых ответов, суммарный размер и обновление таймаута на каждой итерации.
- Расчёты проверяются на известных длительностях 0.1..1.0 секунды и объёмах
  100000..1000000 байт: среднее 0.55 с, объём 5500000 байт, скорость 8 Мбит/с.
  Для этой проверки часы и ответы моделируются в дочернем процессе.
- Ошибка седьмого запроса после шести успешных: дальнейших запросов и итогового
  результата нет.

## Ограничения

Перечислить все возможные отказы ОС, Node.js и сервера невозможно: для остальных
исключений есть общий обработчик. Фатальное исчерпание памяти процесса,
SIGKILL и завершение ОС перехватить этим обработчиком нельзя.
Ответ пока накапливается целиком в памяти; потоковое чтение — возможное улучшение.
Сообщение об ошибке чтения не всегда позволяет отличить разрыв соединения от
повреждённого сжатия, если библиотека не предоставила отдельный код.
